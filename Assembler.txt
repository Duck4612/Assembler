Overview:
The assembler converts a .asm source file into a .osx bytecode file through six phases:
	1) Reading the .asm file
	   The source file is read line by line.

	2) Tokenizing
	   Each line is broken into tokens such as opcodes, registers, numbers, and labels.

	3) Parsing
	   Tokens are validated and organized into instructions or directives.

	4) Label Addressing (First Pass)
	   Label locations are recorded so that branch targets can be resolved.

	5) Byte Encoding (Second Pass)
	   Instructions and directives are converted into byte representations.

	6) Writing the .osx file
	   The header and encoded bytes are written to the output file.

OSX File Header (3 integers, 12 bytes total)

	Name           | Description
	byteSize         Size in bytes of program data (excluding header)
	PC               Address of the first instruction
	loaderAddress    Suggested memory load location (specified at time of assembly)

CLI:

	The assembler will utilize any commandline arguments with full priority, following which the assembler will use (if existing and valid) a file called "AsmOptions.json" in order to obtain arguments.
	The intent is to allow easier repeated use of the assembler in cases of assembling the same .asm file multiple times

	Argument Syntax | Meaning

        <arg>             Denotes arg is a required argument
	[arg]	          Denotes arg is an optional argument
	{arg}             Indicates that {arg} should be replaced with whatever the text inside { } is describing itself to be
	-arg	          Denotes an option flag

	Command Line Argument  | Description
	
	<{inputFile}.asm>    The .asm file to assemble
	[{loaderAddress}]        LoaderAddress is one of the three integers in the .osx byte file header, as described above (note that whether specified or not, loaderAddress will be in the .osx file header, defaulting to 0)
	[-v]                     Verbose mode option flag
	[-o <{outputFile}>]  Optional arg to specify the output file name (default otherwise is {inputFile}.osx)

	Usage: Assembler <inputFile.asm> [loaderAddress] [-v] [-o <outputFile>]
	

Directives:

	Directives are identified by the assembler using '.', and only occupy bytes according to what the specific directive indicates.
	All directives must come before instructions.

	Directive | Operands | Description
	.WORD	    [I]        Allocate 4 bytes optionally initialized with the value of I
	.BYTE       [Label]    Allocate 1 byte of space, optionally initialized with the first char of Label
	.SPACE      <I>        Allocate I bytes of space
	.STRING     <Label>    Allocate 1 byte of space for each char of Label
	.INPUT                 Allocate 4 bytes optionally initialized with user input entered during assembly time.

Instructions:

	Each instruction occupies exactly 6 bytes.

	Byte Layout:
	1 byte   Opcode
	1–5 bytes Operands (registers encoded using 1 byte, immediates/addresses encoded with 4 bytes)

	Unused operand bytes are padded with zero.

	Encoding | Opcode | Operands | Description

        0	   ADR 	    R1 Label   Load the address of Label into R1
        1          MOV      R1 R2      Move the value of R2 into R1
        2          STR      R1 R2      Store the value of R1 into the memory address in R2
        3          STRB     R1 R2      Store the first byte of R1 into the memory address in R2
        4          LDR      R1 R2      Load int (4 bytes) from the memory address in R2 into R1
        5          LDRB     R1 R2      Load byte from the memory address in R2 into R1
        6          BX       R1         Branch to the address in R1
        7          B        Label      Branch to the designated label (put label address into PC)
        8          BNE      Label      Branch to the designated label if comparison register Z != 0
        9          BGT      Label      Branch to the designated label if comparison register Z > 0
        10         BLT      Label      Branch to the designated label if comparison register Z < 0
        11         BEQ      Label      Branch to the designated label if comparison register Z == 0
        12         CMP      R1 R2      Set Z to R1 - R2 
        13         AND      R1 R2      Set Z to R1 & R2 (bitwise AND)
        14         ORR      R1 R2      Set Z to R1 | R2 (bitwise OR)
        15         EOR      R1 R2      Set Z to R1 ^ R2 (bitwise XOR)
        16         ADD      R1 R2 R3   Set R1 to R2 + R3
        17         SUB      R1 R2 R3   Set R1 to R2 - R3
        18         MUL      R1 R2 R3   Set R1 to R2 * R3
        19         DIV      R1 R2 R3   Set R1 to R2 / R3
        20         SWI      I          Software Interrupt with code I to be handled by the kernel
        21         BL       Label      Branch to the designated label after setting R5 to return address (current PC + 6)
        22         MVI      R1 I       Load value of I into R1

Registers:

	Encoding | Register | Description

	0	   R0	      General purpose Register
	1	   R1	      General purpose Register
	2	   R2	      General purpose Register
	3	   R3	      General purpose Register
	4	   R4	      General purpose Register
	5	   R5	      General purpose Register
	6	   SP	      Stack Pointer Register
	7	   FP	      Frame Pointer Register
	8	   SL	      Stack Limit Register
	9	   Z	      Flag Register used for conditional branches
	10	   SB	      Stack Base Register
	11	   PC	      Program Counter (points at next instruction address)

Labels:

	Labels are used to identify addresses for branching purposes and for use of space/values allocated by directives.
	Labels may be used on the same line or on the line preceding what they are labeling. In either case they will be tied to the opcode/directive following it.
	
	Both of the following are valid syntax for label usage:
	
	Label Opcode Operands
	
		or

	Label
		Opcode Operands

Comments:

	Comments are identified by ';', and will cause everything on a given line to be ignored after the ;

Customization:

	If a valid "isa.json" file is present, it overrides the default instruction and/or register definitions. Note that at this time custom instruction sets must still utilize at most 6 bytes per instruction.
	Valid operands are "Register", "Label", and "Number", with "Label" and "Number" indicating 4 bytes for an address or immediate respectively.
	Valid format for defining the default instructions/registers as above is as follows:

	{
		"instructions": [
    		{
    		    "name": "ADR",
    		    "opcode": 0,
       	 	    "operands": ["Register", "Label"]
    		},

			...

    		{
    		    "name": "MVI",
    		    "opcode": 22,
    		    "operands": ["Register", "Number"]
    		}],    
		"registers": [
        	{
        	    "name": "R0",
        	    "code": 0
        	},

			...

        	{
        	    "name": "PC",
        	    "code": 11
        	}]
	}
